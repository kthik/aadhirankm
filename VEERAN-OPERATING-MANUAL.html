Everyone

Start the system

Two processes run together: the API and the web app. Both start from one command.

  1. Open a terminal in the project folder.
  2. The first time only, install dependencies: npm run install:all
  3. Start everything: npm run dev
    • The API prints Veeran API listening on http://localhost:4000 and, above it, the database folder it is using.
    • The web app prints http://localhost:5173.
  4. Open http://localhost:5173 in a browser.
If the page says

"Cannot reach the server, so registration is unavailable and sign-in will fail" — the API is not running. Both halves must be up; start them with npm run dev from the project root, not the client folder alone, then reload.

For a single-process production run, build the web app and let the API serve it: npm run build && npm start, then open http://localhost:4000.

Everyone

Sign in and settings

Every role signs in the same way, with the UID issued at registration.

  1. On the sign-in screen, type your UID — for example SA001, AD001, A001, P001, J001.
  2. Type your password. A brand-new account's password is pass@123.
  3. Press Sign in. You land on your own dashboard.
  4. If a banner says you are still on the default password, change it: open the settings gear in the top bar and use the password section.

The settings gear

  • Day / night / auto — auto follows the computer's setting.
  • English / தமிழ் — switches the interface. Names of people, academies and events are never translated.
  • Change password and Sign out.

Forgotten your UID?

An academy can recover its UID from Forgot your UID? on the sign-in screen by entering the academy name, coach name and phone number — all three must match the registration exactly. Anything else returns "contact an Admin", which is deliberate: it stops the page being used to fish for academy names.

A competitor or judge who has lost their UID should ask an Admin, who can find them by name and reset the password from the drawer that opens when their name is clicked.

Super Admin · SA001

First-time setup

Do this once, in order, before anyone registers. It takes about twenty minutes on a fresh system.

Create the tournament Tournaments tab

  1. Sign in as SA001 and open the Tournaments tab.
  2. Fill in Name and Location — for example "National Silambam Tournament", "Coimbatore".
  3. Fill in Venue address. Competitors see this on the registration form when they pick the tournament, so write the full address.
  4. Set Start date and End date. The end date is inclusive, and the tournament closes itself the day after it.
    • Leaving the end date blank means open-ended — it keeps taking entries until you switch it off.
  5. Press Create tournament. It appears under All tournaments with a record count.
  6. Deactivate the auto-created "Silambam Open" placeholder if you are not using it, so competitors are not offered a choice that does not exist.

Check the events Events tab

  1. Open Events. Six Silambam events are seeded (E001–E006).
  2. To add one, fill Event name, Category (Solo, Pair, Weapon…) and a description, then Create event. It becomes selectable on every registration form immediately.
  3. Use Deactivate on anything you are not running. A deactivated event disappears from registration forms and is rejected if someone submits it anyway.

Create the admins Admins tab

  1. Open Admins. AD001 exists already.
  2. Enter the admin's name. Leave the password blank to issue pass@123, or set one.
  3. Optionally tick the tournaments this admin may see. Leave all unticked to give them everything.
  4. Press create. The UID and password are shown once — copy them and hand them over. They cannot be read back later.
Passwords

Passwords are stored hashed, so nobody — including you — can read an existing one. If somebody loses theirs, reset it: the new value is displayed once, for you to pass on.

Confirm the database location Database tab

  1. Open Database and read the top panel: the folder in use, the driver, and how many rows and Super Admin logins it holds.
  2. For a single laptop, leave the driver on Local JSON.
  3. To share one database across machines, see Move the database — do it now, before any registration, when there is nothing to lose.

Admin · Super Admin

Prepare the competition

Age bands, score criteria and judges — set before the first performance.

Age and score categories Categories tab

  1. Sign in as AD001 and open Categories.
  2. Check the age categories. Five are seeded: Sub-Junior 4–10, Junior 11–15, Cadet 16–18, Senior 19–35, Veteran 36–80.
    • Ranges must not overlap. A competitor's band is worked out from their age, so editing a range immediately re-categorises everyone in it — no re-entry needed.
  3. Check the score categories. Five are seeded: Position, Power, Speed, Stability, Style. Each is marked out of 10, so a sheet totals 50.
    • Five active is the maximum. Deactivate one before adding another.

Register the judges Judges tab

  1. Open Judges → Register a judge.
  2. Enter judge name, academy, location, address and mobile.
  3. Leave the bouts empty for now if the bouts do not exist yet — you can assign them later from the same tab.
  4. Press create and note the UID (J001…) and password shown once.

Clicking a judge's name anywhere opens their drawer: the bouts they hold, the sheets they have filed, and an edit form.

Deactivating a judge

Deactivating or deleting a judge hands back every bout they have not finished, so it shows as unassigned and you can reassign it. A bout they did finish keeps their id, because that is the record of who scored those results — the sheets themselves are never deleted. Reactivating restores their sign-in but not their bouts, which may already belong to someone else.

Academy coach · no account needed to start

Register an academy

A coach registers the academy once, then enrols competitors under it.

  1. Open the app and press Register an academy under "New here?".
  2. Choose the competition in Registering for. The list holds only tournaments that are on now or still to come.
    • Selecting one shows its dates, location and venue address. Check them before continuing — everything you register afterwards is filed under this tournament.
  3. Fill in academy name, coach name, phone (10 digits starting 6–9), location and address.
  4. Press Create academy.
  5. A card shows your UID (A00n) and temporary password. Copy both — the UID is how you sign in from now on.
  6. Press Go to sign in, sign in, and change the password under the settings gear.

Enrol competitors one at a time

  1. On the academy dashboard open Register participant.
  2. Enter participant name, father's name, age (4–80) and mobile.
    • Mobile, address and location are pre-filled from the academy. Overwrite them for a competitor whose details differ.
  3. Tap the events the competitor is entering. A competitor may enter several.
  4. Press register. Their UID and password appear once — pass them to the competitor so they can watch their own results.
  5. Repeat, or use bulk upload for a whole squad.

You do not choose a tournament again: competitors you add inherit the academy's. Track the squad under Participants, and squad progress, entries per event and your podium under Overview.

Individual competitor · no account needed to start

Register as an individual

For a competitor entering without an academy.

  1. Press Register as an individual under "New here?".
  2. Choose the competition in Registering for and check the dates, location and venue address shown underneath.
  3. Enter participant name, father's name, age, mobile, location and address.
  4. Tap every event you are entering.
  5. Press Register and copy the UID (P00n) and temporary password from the card.
  6. Sign in and change the password under the settings gear.

What a competitor sees after signing in

  • My results — events entered, judged, medals, best position, average score and age group, with a per-category breakdown for each judged event.
  • Registered events — the entries and the bout each one sits in.
  • Update profile — correct contact details.

Academy coach · signed in

Bulk upload a squad

One spreadsheet, up to 500 competitors, all or nothing.

  1. Open Bulk upload on the academy dashboard.
  2. Download the template. It carries an Event Codes sheet listing every active event and its code.
  3. Fill one row per competitor: Participant name, Father's name, Age, Mobile, Address, Location, Events participating.
    • Events accepts codes (E001), full event names, or several of either separated by commas or semicolons.
    • Blank Mobile, Address or Location inherit the academy's.
  4. Upload the file. It is read in your browser, so nothing is sent until it parses.
  5. Read the result.
    • All rows valid → everyone is created and the UIDs are listed.
    • Any row invalid → nothing is saved. Each bad row comes back with its spreadsheet row number and the field at fault.
  6. Fix the flagged rows in the spreadsheet and upload the whole file again.
Why all-or-nothing

A half-loaded roster is worse than none: you cannot tell which competitors made it without checking every row by hand. Rejecting the batch keeps the spreadsheet as the single source of truth until it is clean.

Duplicates are refused: the same name and mobile already in your academy is rejected rather than entered twice.

Admin

Build and assign bouts

A bout is a judged group. Competitors are invisible to judges until they are placed in one, so this is the step that makes the competition run.

Create a bout Bouts tab

  1. Open Bouts → Create a bout.
  2. Name it something a judge will recognise from the schedule — "Kambu Solo · Junior · Mat 1".
  3. Optionally scope it to an event and an age category. Scoping is worth doing: the eligible list then narrows to competitors who match both, and the judge sees only that event.
  4. Choose the judge, or leave it unassigned and assign from the Judges tab later.
  5. Create it.

Put competitors in it

  1. Open Assign participants to a bout, or use the Participants tab for larger groups.
  2. Filter the list — by search, event, academy, bout or assignment state. Filter to Not assigned to see who is still waiting.
  3. Tick the competitors, or use Select all shown.
  4. Choose the bout and press Add to bout. Use Remove from bout to take them out again.
Two rules the system enforces

A competitor may hold at most one bout per event — two would mean being judged twice for the same event. And a bout belongs to exactly one judge: assigning a bout that is already held raises a confirmation, and confirming moves it, clearing the previous judge's claim so it is never held twice.

Running order needs no management. Within a bout, competitors entered in more events go first so they have time to prepare for their next event, then queue number decides, and scored competitors drop to the bottom of the judge's list.

Judge · J00n

Score a bout

A judge sees only their own bouts, one tab each, and never the whole competition.

  1. Sign in with your judge UID. Your dashboard opens on your first bout, showing assigned, completed and blocked counts.
  2. Pick the bout tab you are judging. Each tab is named for its event.
  3. Read the running order. Call the competitor at the top who is ready.
    • In other performance, greyed out, means they are performing in another bout right now. They become clickable once that judge files their sheet — carry on down the list and come back.
    • Rows already scored sit at the bottom with their result.
  4. Click the competitor's row to open the score sheet.
  5. Enter a score from 0 to 10 for each category — Position, Power, Speed, Stability, Style. The total updates as you type.
  6. Choose the position: 1, 2, 3 or 4, or Disqualified or Absent.
  7. Submit. You return to the running order with progress updated and the row moved to the bottom.

Correcting a sheet

Click the competitor again. The sheet re-opens pre-filled with what you entered, so submitting a correction is the same action as the original entry. There is no separate edit mode and nothing to unlock.

Progress

Above the running order sits a scored-versus-waiting bar, and per bout: how many are scored, how many pending, and how many podium places you have closed. An admin sees the same figures for every bout at once.

Export what is on screen List view

  1. Open List view and set the filters — event, age group, bout, judge, completion, or free text.
  2. Press the CSV export. The file contains exactly the rows on screen, in the same order.

A competitor entered in several events appears as one row per event, all sharing their registration ID, each showing that event's own bout and result. Filtering by event narrows to that event's rows rather than listing every event of everyone who entered it.

The Super Admin filter bar

  1. Sign in as SA001 and open Overview.
  2. Set any combination of tournament, event, age category, academy and a registered-between date range.
  3. Every panel below re-reads from that selection: headline totals, the splits by event, age band and academy, the trend, and each tournament card. The header states how many competitors matched out of the total.
  4. Press Clear filters to return to everything.

Admin

Champions and medal handover

The podium, and a record of which medals have physically been given out.

  1. Open the Champions tab. Winners are grouped by bout, with gold, silver and bronze totals and an issued percentage.
  2. Call the winners and hand over the medal.
  3. Tick Mark issued on that winner's row.
  4. Confirm in the dialog. The row records who issued it and when, and the box locks.
One-way

Issuing cannot be undone from the interface — handing over a medal is a physical act, not a toggle. The handover is stored separately from the score sheet, so a judge revising a score afterwards cannot erase the record that a medal was given out.

Admin full backup · Super Admin everything else

Backup and restore

One Excel workbook, a sheet per table. Take one at the end of every competition day.

Take a backup

  1. Open Backup & restore → Backup.
  2. For everything, press the download straight away.
  3. For part of the data (Super Admin), set a filter first — tournament, academy, competitor, or a date range — then download.
  4. Store the file somewhere off this machine. The backup history table records what was taken, by whom, when, and its scope.
Backup never deletes

Downloading changes nothing. Clearing records is a separate action, because a download that also wipes data on the way out is far too easy to fire by accident.

Restore a backup Super Admin

  1. Open Restore and choose the workbook.
  2. Read the preview: per table, how many rows are incoming, how many are duplicates, and how many will be added.
  3. Press restore.
    • A row whose id already exists is skipped, never overwritten, so a restore cannot silently replace work done since the backup, and running it twice is safe.
    • If anything fails part-way, every table rolls back.

Clear records Super Admin

  1. Take a backup of the records first.
  2. Set the filter for what should go.
  3. Press the delete action. It reports exactly what it would remove, per table.
  4. Confirm. Without an explicit confirmation nothing is deleted.
Read this before deleting

A backup filter and a delete filter mean different things on purpose. Backing up one competitor includes their academy, bout and judge so the file makes sense on its own; deleting that competitor does not take their academy and judge with them. An academy is only removed by an academy or tournament filter, judges and bouts only by a tournament filter.

Super Admin · Database tab

Move the database

Point the app at a different folder — typically a synced Google Drive folder so several machines share one database. Do it when nothing is live, ideally before registration opens.

Before you start

  • For Google Drive: Drive for desktop must be installed and signed in on this machine. The app has no Google login of its own — it reads and writes the synced folder like any other folder.
  • Run one server against a Drive folder at a time. Drive syncs whole files rather than merging them, so two machines writing at once produces a conflict copy, not a merge.

Change the location

  1. Open Database and note what the top panel says now — folder, driver, rows and Super Admin logins.
  2. Choose the driver: Local JSON or Google Drive.
  3. Fill in the fields.
    • Local — a folder path, absolute or relative to the project.
    • Drive — the folder inside Drive (e.g. Veeran/data). Set the synced Drive folder only if it is mounted somewhere unusual. The account field is a label so it is clear whose Drive holds the data.
    • Leave Keep a local copy for reads ticked unless you have a reason not to: reads then come from local disk and refresh from Drive, and the app still answers reads if Drive goes offline.
  4. Press Check location. Nothing is written. The panel reports the resolved folder and what is already in it, and warns you if it holds a database or has no Super Admin login.
  5. Press Save location. A dialog names the source, the destination and its contents.
  6. Answer the copy question.
    • Yes, copy — every collection is written across, then the app switches. If the destination already holds data you must tick the box confirming it will be replaced.
    • No, just switch — only allowed when the destination already has a Super Admin login. You get an alert that the old data stays on disk but is no longer read.
  7. Type your own Super Admin password and confirm.
  8. Check the panel now reads the new folder, and that the row count looks right. Nothing was deleted from the old folder.
Why a switch can be refused

If you decline the copy and the destination has no Super Admin login, the switch is refused. After it, nobody could sign in to administer the new location — and the real database, with everything in it, would be left behind at the old path. Copy the data across, or point at a folder that already has a Super Admin account.

The change takes effect immediately; no restart is needed. It is recorded in System logs. If an environment variable is overriding the configuration, the panel says so — the variable still wins until it is removed.

Troubleshooting

The symptoms most likely to come up on the day, and what each one actually means.

SymptomCauseFix
Sign-in fails with "Request failed (500)" The API is not running, so the web server has nothing to talk to Run npm run dev from the project root and reload
"New here?" shows no registration links Same cause — configuration could not be loaded, so nothing module-gated renders Start the API. The banner on the sign-in screen names this
The API exits at startup saying no Drive folder was found Driver is Google Drive but Drive for desktop is not installed or signed in here Install and sign in, or start once with VEERAN_DB_DRIVER=local and switch the driver from the Database tab
The tournament dropdown is empty or missing No tournament is active with a start date and an unexpired end date Create one, or extend the end date, in Tournaments
"That tournament is not open for registration" The chosen tournament has ended or been deactivated since the page loaded Reload the form and pick from the refreshed list
A judge cannot click a competitor — "In other performance" The competitor is due in another bout first; this is deliberate Score the rest of the list; the row unlocks when the other judge files their sheet
Assigning a bout asks for confirmation Another judge already holds it, and a bout may only have one judge Confirm to move it, which clears the previous judge's claim
Bulk upload saved nothing At least one row failed validation, and import is all-or-nothing Fix the flagged rows — the row numbers match the spreadsheet — and re-upload the whole file
A restore added fewer rows than expected Rows whose ids already exist are skipped, never overwritten Expected. Use the delete-first option only for a deliberate full replace
An admin cannot see a tournament's data That admin is scoped to named tournaments Add the tournament to them in Admins, or clear their list to make them unrestricted
Reactivating a finished tournament is refused Its end date has passed; the next sweep would switch it off again Extend the end date first, then activate
A medal was issued by mistake Issuing is one-way by design Record the correction outside the system; the audit log shows who issued it and when

Day-of checklist

Before the first performance

Admin

  • Tournament active, dates correct
  • Events for today active, others deactivated
  • Age and score categories checked
  • Every judge registered and able to sign in
  • Bouts created, scoped, and each with a judge
  • No competitor left under Not assigned

At the end of the day

Admin or Super Admin

  • Completion % read off the Overview
  • Any bout still short of 100% chased
  • Champions reviewed, medals marked issued
  • Backup downloaded and stored off the machine
  • System logs skimmed for anything unexpected
